## thunder-strike · 雷霆战机

**在线试玩（网页版，点开就能玩，不用装任何东西）：**

### https://thunder-strike.app.workbuddy.host/

手机、电脑浏览器都能开。竖屏体验更好，建议用手机。

一个雷电（Raiden）风格的弹幕射击游戏：拖动躲弹幕，自动开火，一路打到 Boss。

### 怎么玩

- **拖动** —— 移动飞机。用的是相对偏移，手指不用一直压在机身上，点哪都能拖
- **自动开火** —— 不用按键
- **轻点屏幕空处** —— 放炸弹，清屏（也可以按空格，或点右下角圆钮）
- 桌面端：`空格` 放炸弹 · `P` 暂停 · `R` 重开

### 里面有什么

- **31 种敌人**，从成群的小飞机到带护甲的巨舰，行为各不相同
- **3 个 Boss**，每个有 **13 种弹幕编排**（螺旋、扇射、追踪、弹墙、交叉、布雷……）
- **4 把可切换武器**：连射、激光、波动、散射
- **6 条强化路线**：火力 / 专精 / 僚机 / 装甲 / 军火 / 引擎
- **3 个关卡**，每关三波杂兵 + 一个 Boss

### 技术上比较有意思的几点

- **零依赖，纯 Canvas 2D 手写**，没有用任何游戏引擎
- **所有美术都是代码画出来的**，整个项目没有一个图片资源
- 设计分辨率 750×1334 竖屏，适配安全区
- 平台差异全部收敛在 `src/platform.js` 一个文件里，同一份代码能跑在微信小游戏 / 抖音小游戏 / 网页
- 微信构建产物 **163.7 KB**，占 4MB 主包的 **4.00%**

### 想在本地跑

零构建，浏览器直接打开 `index.html` 就能玩。

需要本地服务器的话：

```bash
node tools/serve.js      # 默认 http://localhost:8123
```

想打包成微信小游戏：

```bash
node tools/build-wx.js   # 产物在 dist/wx，用微信开发者工具导入
```

> 注意：小游戏那边的 appid 目前还是游客 appid，真要上架得先换成自己的。

### 目录

```
thunder-strike/
├── index.html          web 调试壳（按顺序直接引 src/*.js，零构建）
├── src/                游戏源码
│   ├── config.js       所有数值、敌人表、Boss 表都在这
│   ├── platform.js     平台适配层（wx / tt / web 的差异只在这里）
│   ├── entities.js     玩家、敌人、子弹、Boss
│   ├── game.js         主循环与关卡推进
│   └── ...
├── tools/              构建与验证脚本
│   ├── build-wx.js     拼成微信小游戏单文件
│   ├── build-web.js    生成 web 发布副本
│   ├── smoke.js        web 端冒烟（真实事件链路）
│   ├── smoke-wx.js     小游戏端冒烟（跑的是构建产物）
│   ├── stability.js    反复跑套件，抓随机翻车的断言
│   └── mutate.js       变异测试：故意改坏代码，验证断言真的拦得住
└── docs/
    └── ai-game-design-pitfalls.md   踩坑总结，见下
```

### 顺带写了篇踩坑总结

[`docs/ai-game-design-pitfalls.md`](./thunder-strike/docs/ai-game-design-pitfalls.md) —— 从第一行代码到能上线，14 轮迭代里踩过的坑，约 1.5 万字。

核心结论一句话：**AI 做游戏，最贵的不是写代码，是验证。**
里面讲了数值是怎么「悄悄变质」的（难度系数连乘会把对象池打满、关卡表循环会变成锯齿而不是斜坡），
以及最要命的一条：**AI 写的测试会自证正确** —— 断言可能一直是空过的，
唯一可靠的检验办法是亲手把它该拦的 bug 造出来（变异测试）。
